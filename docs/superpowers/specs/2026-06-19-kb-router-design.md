# /kb 统一路由器 — 设计规格

> 日期: 2026-06-19 | 状态: 设计完成

## 1. 背景与目标

### 问题

Knowledge Tracker 当前有 9 个用户可见命令（`/learn`, `/kb-list`, `/kb-detail`, `/kb-deep`, `/kb-quiz`, `/kb-link`, `/kb-delete`, `/kb-assess`, `/kb-rebuild-index`）。用户需要记住每个命令的名称和参数格式，认知负担重。

### 目标

- 将 8 个 `/kb-*` 命令合并为一个 `/kb` 入口
- `/learn` 保持不变（最高频操作，短命令更优）
- 用户用自然语言描述意图，LLM 解析并路由到对应操作
- 不丢失任何现有功能

### 非目标

- 不改变知识库存储格式
- 不改变 knowledge-collector 和 knowledge-profile 内部 skill

---

## 2. 路由器结构

采用**单文件路由器（方案 2）**：一个 `skills/kb/SKILL.md`，前端是意图解析规则，后端是各操作的独立 section。

### 文件组织

```
skills/kb/SKILL.md (~600 行)

  frontmatter            # 元信息 + argument-hint
  路由规则                # 核心 — 意图解析 + 实体提取 + 分发
  [操作] 展示目录          # 空输入 / 筛选分类
  [操作] 查看详情          # 匹配到唯一条目
  [操作] 深入讲解          # 含"深入/讲解/讲讲"关键词
  [操作] 测验复习          # 含"测验/测试/复习"
  [操作] 关联条目          # 含"关联/链接" + 两个实体
  [操作] 删除条目          # 含"删除/移除"
  [操作] 知识评估          # 含"评估/画像"
  [操作] 修复索引          # 含"修复/重建"
  公共工具                # 实体搜索、格式模板、操作引导栏、安全确认
```

## 3. 意图解析 (路由规则)

### 3.1 操作关键词匹配（按优先级）

```
1. 删除 — "删除/移除/去掉/删掉"
2. 关联 — "关联/链接/connect/link"，或自然语言中出现两个已知条目名
3. 深入 — "深入/讲解/讲讲/了解更多/deep dive/展开"
4. 测验 — "测验/测试/quiz/复习/review/考试"
   - 含"统计/stats" → 仅展示统计
5. 评估 — "评估/画像/assess/自评"
6. 修复 — "修复/重建/rebuild/fix/同步索引"
7. 查看 — 所有其他情况（默认）
```

### 3.2 实体提取

1. 从 $ARGUMENTS 去除已识别的操作关键词和停用词（的、一下、帮我、这个、那个、把）
2. 以空格、逗号、"和"、"与"、"跟"、"以及" 为分隔符分割为实体片段
3. 对每个实体片段按顺序匹配 search-index.json：
   - a. entry.id 精确匹配
   - b. entry.title 包含匹配（多个→展示候选项）
   - c. category 目录名匹配
   - d. entry.tags 包含匹配
4. 未匹配到的保留为自由文本（深入方向描述等）

### 3.3 冲突处理

- 同时命中 category 和 entry.id → 优先 entry，附加提示"或查看分类？"
- 提取到 2 个实体但无操作词 → 视为 link 意图
- 命中多个操作关键词 → 按优先级取最高
- 模糊匹配多个候选项 → 展示候选列表让用户选择

## 4. 用户界面

### 4.1 空输入 → 目录 + 引导

展示知识库目录（按 category 分组），底部附带：

```
总计: N 条  |  技: n1  |  道: n2
明天待复习: n3 条

——
💡 试试：
  /kb <条目名>        — 查看详情
  /kb 深入 <条目>     — 追加深入讲解
  /kb 测验            — 开始知识复习
  /kb 评估            — 刷新知识画像
```

### 4.2 查看详情

展示条目全文（含所有历史深入讲解）。底部操作栏：

```
——
📌 你可以：
  /kb 深入 asyncio          — 追加深入讲解
  /kb 测验 asyncio           — 复习此知识点
  /kb 关联 asyncio <其他>    — 关联另一个条目
  /kb 删除 asyncio           — 删除此条目
```

### 4.3 深入讲解

追加内容到条目文件末尾，输出新内容 + 确认。

### 4.4 测验复习

- 空参数或含"测验"但无目标 → 自动选最久未复习条目
- 指定条目 → 出题 → 评估 → SM-2 更新
- 含"统计" → 展示复习统计

### 4.5 关联条目

提取两个实体 → 验证关联性 → 建立双向链接 → 输出确认。

### 4.6 删除条目

展示要删除的条目信息（类型/分类/摘要/深入讲解次数/关联条目数），要求输入完整确认语句 `确认删除 <entry-id>` 才执行。

### 4.7 知识评估、修复索引

沿用原有 skill 的交互逻辑，入口统一到 `/kb`。

## 5. 错误与边缘情况

| 情况 | 处理 |
|---|---|
| 实体匹配失败 | 提示未找到，引导 `/kb` 浏览 或 `/learn` 收集 |
| 模糊匹配多个候选项 | 列出候选项，AskUserQuestion 让用户选择 |
| 关联自我 | 拒绝："不能将条目与自身关联" |
| 删除含"删除 A 关联 B" | 删除优先，提示后续操作 |
| 后台 Agent 失败 | `/kb 修复` 可从文件系统重建索引 |

## 8. 约束

- `/kb` 入口必须在 1 个对话轮次内完成意图解析 + 路由
- 删除、关联等写操作需要用户二次确认（删除强制确认，关联低置信时确认）
- 所有知识库路径解析沿用现有模式（`KB_ROOT` = `~/.claude/knowledge`）
- SKILL.md 不依赖外部脚本，全部通过 Claude 自然语言 + 工具调用来执行
